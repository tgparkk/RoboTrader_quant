# Strategy2: 하이브리드 멀티버스 스윙 전략

## 개요

기존 퀀트 팩터 전략과 **병행 운영**할 새로운 스윙 전략.
구조화된 신호 모듈 위에 블라인드 파라미터 탐색(멀티버스)을 적용하는 하이브리드 접근.

### 목표
- 기존 전략과 **상관관계 낮은** 독립적 수익원 확보
- 소액 시작 → 성과에 따라 기존 전략과 동등 규모까지 스케일업
- 모든 데이터 소스(가격, 재무, 수급, 시장지표, 센티먼트) 활용

### 제약
- 기존 실전매매 시스템에 영향 없어야 함 (DB/API/프로세스 격리)
- 과적합 방어 필수 (워크포워드, 최소 거래 수, 상관관계 체크)

---

## 전략 아키텍처

```
[Signal Modules] → [Combiner] → [Filter] → [Portfolio Builder] → [Exit Manager]
```

### 1. Signal Modules (진입 신호 모듈)

각 모듈은 동일한 인터페이스로 0~100 점수를 반환:

```python
def calculate(stock_code, daily_prices, financial_data, ...) -> float  # 0~100
```

#### 추세 계열 (4개)

| 모듈 | 설명 | 블라인드 탐색 파라미터 | 탐색 범위 |
|------|------|---------------------|----------|
| MA 크로스 | 이동평균 골든/데드 크로스 | 단기(5~20), 장기(40~120) | ~32조합 |
| 채널 돌파 | N일 고가 돌파 | 기간(10~60), 돌파 비율(0~5%) | ~30조합 |
| 신고가 근접 | N일 최고가 대비 근접률 | 기간(20~240), 근접률(90~99%) | ~24조합 |
| ADX 추세강도 | 추세 존재 여부 판단 | 기간(7~28), 임계값(20~40) | ~20조합 |

#### 평균회귀 계열 (3개)

| 모듈 | 설명 | 블라인드 탐색 파라미터 | 탐색 범위 |
|------|------|---------------------|----------|
| RSI 역추세 | RSI 과매도 반등 | 기간(7~21), 과매도(20~40) | ~15조합 |
| 볼린저 반등 | 볼린저 하단 터치 후 반등 | 기간(10~30), 표준편차(1.5~2.5) | ~15조합 |
| 이격도 반등 | 이평선 대비 과도 이격 후 복귀 | MA기간(20~120), 이격률(-5~-15%) | ~20조합 |

#### 수급 계열 (2개)

| 모듈 | 설명 | 블라인드 탐색 파라미터 | 탐색 범위 |
|------|------|---------------------|----------|
| 기관/외인 순매수 | 연속 순매수 감지 | 연속일(3~10), 금액 임계값 | ~16조합 |
| 거래량 돌파 | 평균 거래량 대비 급증 | 기간(5~20), 배율(1.5~5x) | ~20조합 |

#### 변동성 계열 (2개)

| 모듈 | 설명 | 블라인드 탐색 파라미터 | 탐색 범위 |
|------|------|---------------------|----------|
| 밴드폭 수축 | 볼린저 밴드폭 최소화 구간 | 기간(10~30), 수축률 하위(10~30%) | ~15조합 |
| ATR 변화율 | 변동성 확장/수축 전환 | 기간(7~21), 변화율 임계값 | ~15조합 |

#### 펀더멘털 계열 (2개)

| 모듈 | 설명 | 블라인드 탐색 파라미터 | 탐색 범위 |
|------|------|---------------------|----------|
| 가치 저평가 | PER/PBR 기반 저평가 판단 | PER(0~15), PBR(0~1.5) | ~12조합 |
| 실적 모멘텀 | 분기 영업이익 성장률 | 성장률 임계값 | ~8조합 |

**총 13개 모듈, 모듈당 ~20조합**

### 2. Combiner (조합기)

- 각 신호 모듈의 가중치를 탐색
- `final_score = w1*추세 + w2*수급 + w3*변동성 + ...`
- 가중치 이산화: 0 / 0.25 / 0.5 / 0.75 / 1.0

### 3. Filter (필터)

- 시장 레짐: 기존 CRISIS/CAUTION/NORMAL 재활용
- 업종 필터, 거래대금 하한
- 기존 전략 보유 종목 제외 (중복 방지)

### 4. Portfolio Builder

- 상위 N종목 선정 (N은 탐색 파라미터)
- 균등 배분 또는 점수 비례 배분

### 5. Exit Manager (청산)

청산 방식도 멀티버스 파라미터:
- 고정 TP/SL (TP: 5~25%, SL: 3~10%)
- 트레일링 스탑 (고점 대비 하락률)
- ATR 기반 (ATR 배수)
- 시간 기반 (최대 보유일)
- 조합 (TP + 트레일링 등)

## 멀티버스 탐색 전략 (3단계)

### Stage 1: 모듈별 독립 탐색
- 각 모듈을 단독으로 백테스트 (해당 신호 하나만으로 매매)
- 모듈당 ~20조합 x 13모듈 = **~260회** 백테스트
- 목적: 쓸모없는 모듈 조기 제거, 모듈별 최적 파라미터 후보 3~5개 선별
- 예상 소요: 수분

### Stage 2: 모듈 조합 탐색
- Stage 1에서 살아남은 모듈(7~8개)의 가중치 조합 탐색
- 전수조사 대신 그리디 + 랜덤 샘플링:
  1. 최고 단독 모듈에서 시작
  2. 하나씩 추가하며 개선 여부 확인 (그리디)
  3. 상위 조합 주변 랜덤 탐색 (~1,000회)
- 예상 소요: 수십분

### Stage 3: 청산 x 필터 멀티버스
- Stage 2의 상위 5개 진입 조합에 대해:
  - 청산 방식 5종 x 파라미터 ~10조합 = 50
  - 필터 조합 ~20가지
  - 5 x 50 x 20 = **~5,000회**
- 예상 소요: 1~2시간

### 과적합 방어
- **워크포워드 검증**: 2023/2024/2025/2026Q1 연도별 분할
- **최소 거래 수**: 연간 50건 미만 전략 제외
- **기존 전략 상관관계 체크**: 일일 수익률 상관 > 0.5이면 페널티

## 리소스 안전장치

### 연산 보호
- **멀티프로세스 2개** (백테스트 워커)
- 배치 단위: 한 번에 50~100회 백테스트 → 중간 결과 저장 → 다음 배치
- 메모리 관리: 배치마다 결과만 축적, 중간 데이터 해제
- 중단/재개: 진행상황을 파일로 저장, 중단 후 이어서 가능

### DB 보호
- **별도 DB**: `robotrader_strategy2` (새 DB 생성)
- **읽기 전용**: 기존 `daily_prices` 테이블은 SELECT만
- **커넥션 풀 분리**: 기존 시스템과 별도 풀

### API 보호
- 백테스트는 API 호출 없음 (DB의 기존 일봉 데이터만 사용)
- 수급 데이터 신규 수집은 장 마감 후에만 실행
- 기존 Rate Limiter 공유하되 우선순위 낮게

### Git 워크트리
- `git worktree add ../RoboTrader_quant_strategy2 -b strategy2`
- 기존 main 브랜치와 완전 격리
- 공유 인프라(db, api, utils)는 import하되 수정하지 않음
